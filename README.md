# RP2040 Temperature Monitor

RP2040内蔵温度センサを使った学習用ベアメタルファームウェアプロジェクト。
DMA、I2C、リングバッファ、デュアルコアの動作を実機で観察する。

## 目的

本プロジェクトは個人の学習目的で、以下を実機で動作させながら理解することを目指す。

- RP2040のSVDからレジスタ定義を生成し、ゼロから動かすベアメタル開発
- レイヤードアーキテクチャ（App / Service / Driver / HAL / Register / Hardware）
- ADC + DMAによるCPU介入のないサンプリング
- I2C経由のLCD1602表示
- リングバッファによるサンプル蓄積と統計処理
- デュアルコア（Cortex-M0+ ×2）での責務分担
- フェイルセーフ（I2C通信障害の検出と通知）

## 開発プロセス

本プロジェクトは ASPICE V字モデルに準拠した開発プロセスを実践する。
段階2（ベアメタル基盤）までは学習目的のチュートリアルとし、段階2.5以降で本格的に ASPICE プロセスを適用する。

## 構成

第1フェーズはC言語、第2フェーズでRust移植を行う。

## 開発の進め方

ブランチ運用や issue 管理など、開発の流儀については [CONTRIBUTING.md](CONTRIBUTING.md)を参照。

## 開発環境

VSCode + Dev Containersが前提。リポジトリを開いて`Reopen in Container`を選択すれば環境が立ち上がる。

## ドキュメントのビルド

```bash
make html
```

成果物は`_build/html/index.html`で閲覧できる。

### クリーンビルド

要件の構造変更（リレーション追加・削除など）を行った場合、キャッシュの影響でリレーションが正しく表示されないことがある。
その場合はクリーンビルドする：

```bash
make rebuild
```

または：

```bash
make clean && make html
```

## ローカルサーバで確認

```bash
make serve
```

`http://localhost:8080`でブラウザから確認できる。

## 要件の規模

- システム要件: 7個(SYS_001〜007)
- アーキテクチャ要件: 6個(ARC_001〜007、ARC_004 は欠番)
- ソフトウェア要件: 43個(SWR_001〜044、SWR_032 は欠番)
- ADR: 4個(ADR-0001〜0004)

要件IDは欠番を許容する。過去のPR・issue・コミットメッセージからの参照を壊さないため、
一度採番したIDのリナンバーは行わない。

## 設計判断のメモ

各要件の`rationale`フィールドに簡潔な理由を記述し、検討過程を伴う判断は
[ADR](docs/common/adr/)として記録している。

メタデータ（frontmatter、要件ID、コード内のトレースタグ）の管理方針は
ADR-0004 に定め、`scripts/metadata_lint.py`によりCIで機械的に検証している。
