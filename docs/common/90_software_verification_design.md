# ソフトウェア検証設計

> **位置づけ**：本ドキュメントは ASPICE [SWE.6（Software Verification）](https://en.wikipedia.org/wiki/Automotive_SPICE) に該当する。
> ソフトウェア要件（`20_software_requirements.md`）の各要件に対し、統合されたソフトウェアがそれを満たすことを確認する検証ケースを定義する。
> 各 SWV は、対応するソフトウェア要件（SWR_NNN）へのトレースを持つ。

本書では、承認済みのソフトウェア要件に対する検証ケースを、要件の派生元システム要件ごとに整理して記述する。
検証の実施は段階4-4 で行う。

## 検証手段の分類

各検証ケースは `method`属性で検証手段を示す。分類は IADT に従う。

| 値 | 手段 | 内容 |
| --- | --- | --- |
| `inspection` | 検査 | 成果物を目視または静的解析で確認する。実行を伴わない |
| `analysis` | 解析 | 計算・モデル・シミュレーションにより間接的に確認する |
| `demonstration` | 実証 |実行し、期待する動作が観測できることを確認する。定量的な計測を伴わない |
| `test` | 試験 | 実行し、定量的な合否基準に対して計測値を判定する |

`environment` 属性は検証を実施する環境を示す。`host`（開発マシン上）、
`target`（RP2040 実機）、`ci`（GitHub Actions）、`review`（人手による確認）のいずれか。

## 検証ケースの構成

各検証ケースは以下の3項目を持つ。

- **前提条件**：検証を実施できる状態の定義。依存する実装段階と必要な計測手段
- **手順**：実施者が再現できる粒度の操作列
- **合否基準**：観測結果に対する判定条件。可能な限り数値で表現する

1つの検証ケースで複数の要件を確認できる場合は、`verifies` に複数の要件 ID を列挙する。

前提条件には、対象要件を実装したソフトウェアが動作していることと、観測手段が利用できることを書く。
実装を担当する段階番号や内部コンポーネント名は書かない。
SWE.6 は統合されたソフトウェアが要件を満たすことを確認するプロセスであり、内部構造への言及はコンポーネント検証（SWE.5.2）の領域である。
またアーキテクチャは段階2.5-1 で作り直すため、現時点のコンポーネント名を埋め込むと再設計の結果に連動して修正が必要になる。

本書で初出の略語は、初出箇所で展開形を併記する。

## SYS_001（温度の継続的変化可視化）からの派生要件の検証

```{swverif} ADC初期化と温度センサチャネル選択の確認
:id: SWV_001
:status: draft
:method: demonstration
:environment: target
:verifies: SWR_001

**前提条件**

- SWR_001 を実装したソフトウェアが RP2040 実機で動作していること
- UART ログ出力が利用できること

**手順**

1. ADC 初期化後、ADC の制御レジスタと入力選択レジスタの値を UART に出力する
2. 温度センサのバイアス有効化ビットの状態を UART に出力する
3. ADC 変換を1回実行し、取得した生値を UART に出力する

**合否基準**

- 入力チャネルとして ADC チャネル4 が選択されていること
- 温度センサのバイアスが有効であること
- 取得した生値が 0 でも 0xFFF でもないこと（室温付近で飽和していないこと）
```

```{swverif} サンプリング周期100Hzの計測
:id: SWV_003
:status: draft
:method: test
:environment: target
:verifies: SWR_003

**前提条件**

- SWR_003 を実装したソフトウェアが RP2040 実機で動作していること
- GPIO のトグル出力をロジックアナライザまたはオシロスコープで観測できること

**手順**

1. ADC サンプリング開始時に GPIO をトグルする計測用コードを有効化する
2. 10 秒間動作させ、トグル間隔を記録する

**合否基準**

- トグル間隔の平均が 10ms ± 0.1ms の範囲内であること
- 連続する 1000 回の計測で 10ms ± 0.5ms を外れる回数が 0 であること
```

```{swverif} I2Cバス初期化と通信確立の確認
:id: SWV_004
:status: draft
:method: demonstration
:environment: target
:verifies: SWR_004
:open_params: TBD-010 I2C速度が未確定のため、合否基準の通信速度は仮置き。解決時期: 段階3-2。TBD-017 GPIO割り当てが未定のため、観測対象のピンは未確定。解決時期: 段階3-2。

**前提条件**

- SWR_004 を実装したソフトウェアが RP2040 実機で動作していること
- I2C の SCL（Serial Clock Line、シリアルクロック線）と SDA（Serial Data Line、シリアルデータ線）をロジックアナライザまたはオシロスコープで観測できること

**手順**

1. I2C 初期化後、LCD1602 のアドレスに対してダミー書き込みを1回行う
2. SCL のクロック周波数を計測する
3. 9 クロック目における ACK（Acknowledge、受信確認応答）の有無を観測する

**合否基準**

- SCL の周波数が 100kHz ± 10% の範囲内であること
- スレーブから ACK が返ること（NACK ではないこと）
- バスがアイドル時に SCL・SDA ともに H レベルに保持されていること（プルアップが効いていること）
```
