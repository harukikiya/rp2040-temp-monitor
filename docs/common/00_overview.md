# プロジェクト概要

> **位置づけ**：本ドキュメントは本プロジェクト全体の概要と、ASPICEプロセス対応の方針を示す。
> 各設計文書を読む前に、まず本ドキュメントを読むことを推奨する。

## プロジェクトの目的

RP2040の内蔵温度センサを使った学習用ファームウェアプロジェクト。
DMA、I2C、リングバッファ、デュアルコア活用の動作を実機で観察することを目的とする。
実装言語はC言語（第1フェーズ）、その後Rust（第2フェーズ）。

## ハードウェア前提

本プロジェクトは以下のハードウェア構成を前提とする：

- **MCU**：Raspberry Pi Pico（RP2040、Cortex-M0+ デュアルコア、264KB SRAM、外付け 2MB QSPIフラッシュ W25Q16JV）
- **温度センサ**: RP2040 内蔵温度センサ(ADC4 経由)
- **表示**：I2C接続のLCD1602（16文字×2行 LCD）
- **状態表示**：オンボード LED（GPIO 25）
- **書き込み**：USBマスストレージモード経由でUF2ファイル

## ASPICEプロセス対応

本プロジェクトは Automotive SPICE 4.0（PAM v4.0）の V字モデルに準拠したプロセスで進める。
プロセスの名称および略称は 4.0 の定義に従う。3.1 とは V字右側の名称が異なり、
特に SWE.6 は 3.1 の Software Qualification Test（適格性確認テスト）から
Software Verification（ソフトウェア検証）に改称されている点に注意する。

なお SWE.2.1 / SWE.2.2 および SWE.5.1 / SWE.5.2 の細分は規格上の区分ではなく、
アーキテクチャ設計とコンポーネント設計、コンポーネント検証と統合検証を別の成果物として
扱うための本プロジェクト独自の記法である。4.0 の SWE.5 はこの 2 側面を 1 プロセスに含む。

採番と版の選定の根拠は [ADR-0006](adr/0006-vmodel-document-numbering.md) を参照。

### SYS.3 を省略する判断

本プロジェクトはハードウェアが既に決まっており（Raspberry Pi Pico）、ハードウェアとソフトウェアの分担を改めて設計する必要がない。
ハードウェア構成は上記「ハードウェア前提」セクションで明文化することで、SYS.3の文書化は省略する。

将来、ハードウェアの選択肢が複数になる場合（例：RP2350への移植検討）では、SYS.3として別文書を起こす可能性がある。

### 検証設計のタイミング

ASPICE V字モデルに従い、V字の左側の各成果物に対して、対になる検証をペアで設計する：

- SWE.1（ソフトウェア要件） → ソフトウェア検証設計（段階2.5-0-4）
- SWE.2.1（アーキテクチャ設計） → 統合検証設計（段階2.5-1）
- SWE.2.2（コンポーネント設計） → コンポーネント検証設計（段階2.5-2）
- SWE.3.1（詳細設計） → ユニット検証設計（段階2.5-3）

これらの検証設計文書は段階2.5で作成し、段階4で検証を実施する。

文書番号はこのペア関係を反映しており、対応する 2 文書の番号の和は 110 になる。

```text
20 ←→ 90    SWE.1 ←→ SWE.6      段階2.5-0
30 ←→ 80    SWE.2.1 ←→ SWE.5.1  段階2.5-1
40 ←→ 70    SWE.2.2 ←→ SWE.5.2  段階2.5-2
50 ←→ 60    SWE.3.1 ←→ SWE.4    段階2.5-3
```

番号が大きいほどV字の後ろに位置し、検証設計文書では番号が大きいほど上位の検証レベルになる。

## 段階構成

本プロジェクトは以下の段階で進める：

- 段階1：要件分析（SYS.2、SWE.1）
- 段階2：ベアメタル基盤構築（チュートリアル位置づけ）
- 段階2.5：設計フェーズ（SWE.2.1〜SWE.3.1と、対になる検証設計）
- 段階3：実装フェーズ（SWE.3.2）
- 段階4：検証の実施フェーズ（SWE.4〜SWE.6）
- 段階5〜9：Rust移植
- 段階10：言語比較ドキュメント

進捗状況の詳細は [README.md](https://github.com/harukikiya/rp2040-temp-monitor/blob/master/README.md) を参照。
